# RiskProbe 风控 AI Agent 设计

日期：2026-08-05  
状态：已确认设计，待实施计划  
目标周期：10 个工作日

## 1. 背景与目标

本项目面向金融风控中的规则发现和异常感知，建设一套“确定性风控引擎 + Kiro Agent 编排”的可审计分析系统。项目不让大模型直接读取用户明细、猜测规则阈值或自由执行代码；候选规则生成、指标计算、稳定性验证和异常归因均由本地 Python 工具确定性完成，Kiro 负责理解分析目标、选择白名单工具、检查证据是否充分并生成报告。

项目同时形成两个隔离版本：

1. **公开版 RiskProbe Agent**：使用公开信用行为数据及合成订单/浏览行为，作为可开源、可复现的个人项目经历。
2. **公司版 JointRisk Copilot**：读取公司环境中的本地 Parquet 联合建模宽表，辅助订单、浏览、高危多头和序列 Embedding 特征的规则发现、跨机构验证及异常诊断，作为实际落地后可写入实习经历的提效项目。

项目要回答的核心问题不是“如何让大模型生成更多规则”，而是：如何在标签窗口不完整、跨机构客群差异、多重规则搜索、时间漂移和业务约束下自动排除伪规则，并为候选规则建立可复核、可追溯的证据链。

## 2. 设计原则

- **确定性计算优先**：统计指标、规则搜索和异常检测由固定 Python 实现完成。
- **证据先于结论**：没有通过证据门控的规则不得进入稳定规则清单。
- **数据最小暴露**：Kiro 只接触脱敏聚合指标，不读取用户级明细。
- **公开与公司隔离**：公司数据、字段、规则阈值、配置和结果不得进入公开仓库。
- **人工最终决策**：Agent 只生成候选规则和诊断建议，不自动上线或修改策略。
- **可降级运行**：没有 Kiro 时，CLI 仍可完整执行底层分析。
- **不夸大业务语义**：已知 `target=1` 表示坏账；`huisu_date` 仅定义为客户指定的样本截面日期和特征回溯基准日。标签表现窗口未确认时，不声明严格的线上可用性或无时间穿越。

## 3. 范围

### 3.1 公开版

公开版使用 Home Credit Default Risk 多源数据构造申请、历史申请、分期还款、POS 和信用卡余额等信用行为特征，同时提供合成订单/浏览事件生成器，用于植入具有真值的风险规则和数据漂移。

公开版包含：

- 数据契约和元数据等级；
- 多源行为特征加工接口；
- 单变量及二阶组合规则发现；
- Train、Test 和时间切片验证；
- 跨客群稳定性验证；
- 行为漂移注入、异常检测和根因诊断；
- 规则证据卡、审计产物和 Markdown 报告；
- CLI 与 Kiro Agent 适配层。

公开版不宣称跨机构验证，因为公开数据没有与公司客户机构等价的字段。

### 3.2 公司版

公司版读取已在公司环境中生成的本地只读 Parquet 宽表。宽表包含脱敏样本标识、客户指定截面日期、机构、坏账标签和已加工的脱敏特征。

公司版包含：

- Parquet 大宽表惰性扫描和列裁剪；
- 订单、浏览、高危多头和 Embedding 特征族识别；
- 行为时间窗口逻辑校验；
- 全局、机构特有及跨机构失效规则发现；
- 按机构和时间切片的覆盖率、坏账率、Lift 及衰减分析；
- 特征包覆盖率、标签率、客群结构和规则效果异常检测；
- 根因贡献排序及内部人工复核报告；
- Kiro 白名单工具编排和本地审计。

### 3.3 明确不做

首期不包含 SQL、Spark SQL、数据仓库连接、Web 前端、在线流处理、自动策略上线、任意 Python 代码执行、多 Agent 角色扮演、强化学习、外部 LLM API 依赖，也不替代现有 LightGBM 评分模型。

## 4. 数据契约

### 4.1 公司版字段角色

```yaml
dataset:
  id: joint_model_snapshot
  path: /approved/local/path/modeling_sample.parquet
  format: parquet
  read_only: true

columns:
  entity: md5_phone
  snapshot: huisu_date
  institution: institution
  target: target

target:
  positive_value: 1
  positive_meaning: bad_debt
  performance_window: unknown

snapshot:
  meaning: customer_specified_feature_cutoff

features:
  order_prefixes: [order_]
  browse_prefixes: [browse_]
  multiloan_prefixes: [multi_]
  embedding_prefixes: [emb_]
```

实际公司配置使用真实脱敏列名，但不得复制到公开仓库。

### 4.2 元数据等级

- **A**：标签含义、截面日期、表现窗口和特征截止边界完整，可进行严格时间验证。
- **B**：可进行规则发现和跨时间切片验证，但存在标签成熟度等元数据缺口。
- **C**：疑似标签穿越或样本构造异常，仅允许数据诊断。
- **D**：数据契约不通过，停止分析。

当前公司数据预期为 B 级：坏账标签与样本截面日期角色已知，但标签表现窗口尚未确认。因此报告使用“跨时间切片稳定性”，不直接宣称“严格生产 OOT 验证”。

## 5. 总体架构

```text
Kiro Custom Agent
  └── 目标理解、工具选择、证据检查、报告总结
          │
          │ 白名单调用，禁止任意文件路径和任意代码
          ▼
Local MCP / CLI Tool Layer
  └── inspect、discover、validate、monitor、diagnose、report
          │
          ▼
Deterministic Risk Engine
  ├── 数据契约与元数据门控
  ├── 行为特征质量检查
  ├── 候选规则发现
  ├── 规则证据门控
  ├── 异常检测与根因排序
  └── 审计产物与报告
          │
          ▼
本地只读 CSV / Parquet / DataFrame
```

CLI 和 MCP 调用同一组 Python 服务函数，确保 Agent 模式与非 Agent 模式的指标一致。

## 6. 核心组件

### 6.1 数据检查器

`inspect_dataset` 负责：

- 验证主键、截面日期、机构、标签和特征列；
- 检查标签取值、正类率和单一标签切片；
- 检查日期解析、重复样本、常量列、高缺失列和异常取值；
- 识别元数据缺口并给出等级；
- 检查可能的时间穿越特征或结果型字段；
- 输出不包含用户级明细的聚合 Profile。

### 6.2 行为特征目录

每个特征可带以下元数据：

```text
feature_name | family | window_days | aggregation | source | value_type
```

特征族包括订单、浏览、高危多头和 Embedding。元数据优先来自显式配置；缺失时可按脱敏前缀和命名模式识别，无法识别的特征进入 `unknown` 特征族，不臆测业务含义。

行为特征专属校验包括：

- 累计量满足 `7d ≤ 30d ≤ 90d ≤ 180d ≤ 365d`；
- 比例值位于 `[0, 1]`；
- 行为间隔不为负数；
- 次数为零时金额和活跃天数满足配置约束；
- 区分“无行为”和“数据未匹配”；
- 检查某机构或时间切片的整个特征包是否失去覆盖；
- 标记相邻窗口高度相关导致的重复规则。

### 6.3 候选规则发现器

`discover_rules` 通过固定算法生成候选规则：

- 数值特征：分位点、最优分箱及 LightGBM 有效分裂点；
- 类别特征：类别坏账率、频数合并和稀有类别处理；
- 二阶组合：仅在初筛后的高 IV 或高增益特征中，通过浅层决策树和 Beam Search 搜索；
- 行为趋势：短窗口相对长窗口日均的变化；
- 跨源组合：订单与浏览、行为与多头、统计特征与 Embedding 的组合。

规则只在 Train 中产生。Test 和时间切片只能用于验证，不参与阈值搜索。

### 6.4 规则证据门控

`validate_rules` 为每条规则生成证据卡，包含：

- 样本量和覆盖率；
- 命中组与未命中组坏账率；
- Lift、Precision 和 Recall；
- Bootstrap 置信区间；
- Train、Test 和时间切片表现；
- 分机构表现及方向一致率；
- Lift 衰减率；
- Benjamini-Hochberg 多重检验校正；
- 与已有规则的重叠率和冗余度；
- 元数据等级和使用限制。

规则分级：

- `Stable`：跨数据集、时间和适用客群稳定，可进入人工复核；
- `Local`：仅部分机构或客群有效，必须限定适用范围；
- `Unstable`：Test 或时间切片明显衰减；
- `Suspicious`：疑似穿越、样本过小、置信区间过宽或统计偶然。

默认阈值由配置控制。项目报告不得把阈值通过写成业务上线标准。

### 6.5 异常检测与根因诊断

`detect_anomalies` 覆盖四类异常：

1. 数据异常：字段缺失、类型变化、重复率和覆盖率突变；
2. 客群漂移：PSI、缺失率、分位数和机构构成变化；
3. 标签异常：整体及分机构坏账率变化；
4. 效果异常：模型 AUC/KS、规则 Lift 和 Top-decile Lift 衰减。

`diagnose_anomaly` 使用 PSI 贡献、机构构成、特征族覆盖、缺失模式和规则命中变化进行根因排序。诊断结果必须指向可计算证据，LLM 不得凭语言相似性生成根因。

特征包级诊断示例：浏览特征包覆盖率从某时间切片开始下降，主要集中在一个机构，影响一组浏览变量并导致历史规则 Lift 同步衰减。

### 6.6 报告器

公司版报告固定包含：

1. 数据与元数据概况；
2. 阻断项和使用限制；
3. 全局稳定规则；
4. 机构特有规则；
5. 时间衰减规则；
6. 数据、标签和特征包异常；
7. 根因贡献排序；
8. 人工复核建议；
9. 运行配置和审计记录。

## 7. Agent 状态机

```text
接收目标
  → 检查元数据
  → 选择规则发现或异常诊断工具
  → 获取脱敏聚合结果
  → 检查证据是否充分
  → 必要时调整一次参数重新验证
  → 生成报告
  → 等待人工确认
```

约束：

- 最多自动重试一次；
- 规则未经 `validate_rules` 不得进入结论；
- 元数据低于 B 级时不得输出稳定规则；
- Agent 不得读取任意文件、执行任意 Python、修改原始数据或访问外部网络；
- 公司版 MCP 只返回固定 Schema 的聚合 JSON；
- Agent 不得自动上线、删除或修改风控策略。

白名单工具：

- `inspect_dataset(dataset_id)`；
- `discover_rules(dataset_id, objective, constraints)`；
- `validate_rules(dataset_id, rule_ids, split_config)`；
- `detect_anomalies(reference_run_id, current_dataset_id)`；
- `diagnose_anomaly(alert_ids)`；
- `build_report(run_id, report_type)`。

## 8. 本地 Parquet 处理

公司版不负责拉取数据，也不包含 SQL。输入是现有本地 Parquet 宽表。

处理策略：

- 使用 Polars `scan_parquet` 惰性扫描；
- 利用 Parquet 列裁剪，仅读取当前批次字段；
- 先读取主键、机构、截面日期和标签完成样本概况；
- 每批扫描约 50 至 100 个特征；
- 规则发现阶段使用按标签、机构和时间分层的代表性样本；
- 候选规则生成后，只读取候选规则涉及的列并在完整原始分布上复核；
- 每批结果落入运行目录后释放内存；
- 原始 Parquet 始终只读，运行产物不包含用户级明细。

抽样只负责生成候选规则，最终覆盖率、坏账率、Lift 和稳定性证据必须在未改变分布的数据上计算。

## 9. 公开版实验

公开版包含两条实验路径。

### 9.1 Home Credit 多源信用行为

在 Python 中从申请、历史申请、分期还款、POS 和信用卡余额表构造行为次数、金额、活跃月份、最近行为间隔、逾期比例和多来源交叉特征。公开数据适配器和公司数据适配器共享统一数据契约，不共享任何公司代码或配置。

### 9.2 合成订单/浏览行为

生成事件 Schema：

```text
user_id | event_time | event_type | amount | page_type | channel
```

植入已知风险模式和漂移：

- 浏览激增但转化下降；
- 深夜浏览占比上升；
- 订单取消率突增；
- 多平台访问集中爆发；
- 某渠道埋点覆盖中断；
- 指定规则在后续时间切片失效。

漂移实验覆盖缺失率、数值分布、客群结构、标签率、Schema 和规则衰减六类异常，并计算特征级 Precision、Recall、误报率及根因 Top-K 命中率。

## 10. 运行产物与可复现性

每次运行生成不可变目录：

```text
runs/<run_id>/
├── manifest.json
├── metadata_report.json
├── data_profile.json
├── candidate_rules.parquet
├── evidence_cards.json
├── anomaly_alerts.json
└── risk_report.md
```

`manifest.json` 保存数据指纹、配置哈希、代码版本、随机种子和运行时间。相同数据、配置和代码版本应得到一致的规则表达式、指标和排序。

## 11. 错误处理

- 缺少标签、机构或截面日期：阻断并报告字段；
- 某切片只有单一标签：跳过效果指标并保留数据告警；
- 规则命中样本不足：标记 `insufficient_support`；
- 正类过少：不输出不可靠点估计，报告置信区间不足；
- 特征全空或常量：移出搜索并记录原因；
- 时间窗口逻辑冲突：标记特征族异常，不用于稳定规则；
- 内存超限：缩小特征批次，不自动缩减最终验证样本；
- MCP 调用失败：最多重试一次，随后记录失败审计；
- 报告生成失败：保留结构化中间产物，允许单独重建报告。

## 12. 安全与隐私

- Agent 只传入已登记的 `dataset_id`，不接受任意路径；
- 数据目录不加入 Kiro 上下文资源；
- 禁止通用 Shell、文件读取、网络访问和任意代码工具；
- MCP 返回结果不得包含主键、原始样本、未脱敏字段或原始日志；
- 低于最小分组样本量的指标不返回；
- 工具调用记录运行 ID、参数摘要、结果哈希和失败原因；
- 公司配置、数据和结果不进入公开 Git；
- Kiro 只生成分析解释，不改变确定性计算结果。

## 13. 验证策略

实施时加入以下最小自动化验证：

1. 使用手算小样本校验坏账率、Lift、PSI、KS 和 Bootstrap 区间；
2. 验证规则阈值只从 Train 生成；
3. 验证相同随机种子得到相同规则排序；
4. 验证行为时间窗口约束和特征族异常；
5. 对六类注入异常计算 Precision、Recall 和根因 Top-K 命中率；
6. 检查 MCP 输出不存在主键、样本行和未授权字段；
7. 检查 CLI 与 MCP 对同一输入返回一致指标；
8. 使用宽表生成器验证分批扫描和列裁剪，避免加载完整特征矩阵。

## 14. 成功标准

### 14.1 公开版

- 无模型 API 时可通过 CLI 完整运行；

- 相同运行条件产生可复现结果；
- 公开仓库不包含公司数据、代码、配置或结果。

### 14.2 公司版

- 能读取现有本地 Parquet 宽表且不修改源文件；
- 能分批处理订单、浏览、高危多头和 Embedding 特征；

## 16. 指标采集与简历边界

公司版部署后记录：

- 数据检查、规则筛选、分机构验证和报告整理的人工耗时及 Agent 辅助耗时；
- 候选规则数、通过证据门控数、人工复核通过率和新增有效规则数；
- 跨机构方向一致率和时间切片 Lift 衰减；
- 注入异常召回率、误报率、根因 Top-3 命中率和平均定位时间；
- 相同配置重复运行一致率及结论证据覆盖率。

耗时下降率定义为：

```text
（原人工耗时 - Agent 辅助耗时）/ 原人工耗时
```

公开版可写为独立项目经历，但公司版只有在真实运行并获得结果后才能加入实习经历。不得预先编造覆盖机构数、提效比例、规则数量或检测指标。

安全的非量化项目表述为：

> 开发联合建模规则发现与异常诊断 Agent，面向本地 Parquet 脱敏建模宽表构建元数据门控、行为特征规则搜索、跨机构稳定性验证及特征包漂移诊断能力；通过 Kiro 编排白名单 Python 工具，仅返回聚合证据和人工复核报告。

完成真实试运行后，再用实际测量值替换为量化表述。
