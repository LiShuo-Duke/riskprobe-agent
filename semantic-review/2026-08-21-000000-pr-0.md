# Manifest-backed artifact counts and terminal-report contract

The CLI now derives `artifact_count` from the verified immutable run manifest instead of a stale constant, matching the existing local tool-handler path. `RunResponse` requires a non-negative count, and both CLI tests compare the response with that run’s manifest. The RiskProbe skill and changelog add the requested terminal-summary, privacy, and exact-retry contract without changing the two public MCP tool schemas.

Watch for: none.

**Verdict**: APPROVED

## High-level view

The count flow is `service.run()` → `_verified_run_context()` → `manifest.json` → `len(manifest["artifacts"])`. Terminal report sidecars remain outside manifest membership and therefore outside the public count.

Removing the DTO default makes every producer supply the count. Both known constructors do so, and the tests use the generated manifest rather than another hardcoded total.

The Host guidance treats returned structured fields as the only source for the 24-stage and TOP10 summaries. It permits only logical report filenames and limits orchestration-failure recovery to an exact replay of the original decision inputs.
