# Clean no-action review state

The change adds an explicit `no_action_required` terminal decision and causes the reviewer to skip only the missing-evidence and missing-diagnosis gates. The contract limits that flag to a clean, approved, non-retry decision. However, adding the field changes every serialized `ReviewDecision`, and the strict persisted-result decoder still accepts only the old review-field set. **Watch for:** **confirmed** ordinary agent results can no longer be reloaded after publication, causing later requests for the same run to fail closed as unavailable state.

**Verdict**: NEEDS_CHANGES

## High-level view

`ReviewDecision` is persisted as part of `AgentResult` through `model_dump(mode="json")`. Pydantic emits the new defaulted field, so every newly published result contains `review.no_action_required: false`; `AgentResultStore.load()` rejects that payload before result validation. The added tests exercise tool failure and permission denial, but not the remaining gates that must stay active when evidence/diagnosis omissions are intentionally suppressed.

## Persisted AgentResult decoding rejects every newly written review

**Confirmed.** `AgentResultStore.publish()` serializes the entire `AgentResult` via `model_dump(mode="json")`, so the defaulted `ReviewDecision.no_action_required` is present even on ordinary approval and rejection paths. The strict decoder in `src/riskprobe/agents/results.py` requires `review` to contain exactly `approved`, `reason_codes`, `evidence_ids`, and `retry_allowed`; it therefore rejects the payload produced by the publisher. `RiskProbeService.orchestrate()` loads a cached result before reusing a run and maps this failure to `agent_state_unavailable`, so the regression is not limited to the new no-action mode. Add the field to the allowed decoded schema, pass it into `ReviewDecision`, and cover publish/load round trips for both default and no-action decisions.

## Safety-gate behavior lacks no-action regression coverage

**Confirmed.** The reviewer retains the payload-safety, Grade-B production-action, retry-limit, evidence-mismatch, permission, and tool-failure checks, and returns the requested flag only when the result approves. The new tests prove the clean path and two terminal failures, but do not prove the remaining gates still reject when evidence/diagnosis omissions are intentionally suppressed. A future refactor could accidentally gate any of those checks on `no_action_required` without failing this suite. Add focused parameterized calls with `no_action_required=True` for each remaining required safety gate and assert the denial reason, cleared flag, and no retry where applicable.
