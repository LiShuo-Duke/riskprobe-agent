# Evidence-validated terminal replay for new Host idempotency keys

The change reconciles a cached non-empty `AgentResult` with a new Host idempotency key by replaying an already-reviewed terminal session's immutable decision evidence. The new key must submit the exact original proposal before receiving the outcome; conflicting actions remain unavailable, and same-key/no-action replay is unchanged. Context, proposal, result, provider, diagnosis, actions, and evidence IDs are bound without synthesizing a decision. A cache-publication race still leaves a normal new key permanently failed with `agent_state_incomplete`.
Watch for: **confirmed blocker** — result publication precedes Host terminalization while reconciliation skips in-flight matches; **likely residual concern** — discovery sees only the coordinator's in-memory session snapshot.
**Verdict**: NEEDS_CHANGES

## High-level view

Normal replay copies the prior context and outcome only after `DecisionController.replay()` reconstructs the exact aggregate evidence graph. The new key must independently submit the identical canonical proposal.

The cache and Host session commit separately. A second key can load the published result while the first key still has `done == False`; replay skips that candidate and persists `agent_state_incomplete`.

Replay scans only `_sessions`. A coordinator initialized before another coordinator commits the terminal does not refresh the store before reconciliation.

<details><summary>Details</summary>

## Published result can outrun Host terminalization

**Confirmed blocker.** `RiskProbeService.orchestrate()` publishes the result at `service.py:2005` before `HostDecisionCoordinator._execute()` builds the first key's terminal outcome. Key B can load that cache in the intervening window and enter `_terminal_replay_for()` first. The scan skips key A while `candidate.done` is false (`host_decision.py:664-669`), then key B fails normal-result no-action validation and permanently records `agent_state_incomplete`.

Before declaring the result incomplete, reconciliation must detect a matching in-flight session by immutable run/context identity, wait for bounded completion, and retry validation. Failure and timeout must remain fail-closed.

## Replay discovery misses later cross-coordinator commits

**Likely residual concern.** Persisted sessions load only during construction (`host_decision.py:409`), while `_terminal_replay_for()` scans only the in-memory dictionary (`host_decision.py:662`). A coordinator started before another coordinator commits key A never sees that terminal when its key B receives the shared cache, so it also records `agent_state_incomplete`.

If overlapping coordinators sharing `state_dir` are supported, refresh and validate persisted candidates under the existing store lock before concluding no replay exists. Otherwise, make the single-coordinator invariant explicit and test it.

## Proposal-less terminal restart is not covered

**Likely residual concern.** The integration test submits key B in the same coordinator lifetime; it never reloads the newly persisted normal terminal with `proposal is None`, the storage shape consumed by the new `submit_proposal()` branch.

Add a test that completes A, obtains B's context, restarts the coordinator, rejects a conflicting B proposal, and accepts the exact proposal. An evidence-tamper variant must remain unavailable.
