# 可选 Scorecard 工件与评分流程

本改动默认关闭 scorecard；启用后以 Train 拟合 WOE/逻辑回归模型，并对 Test 和非空 Holdout 冻结评分后输出聚合摘要。资格不足时 scorecard 记录为 `unavailable`，规则流程仍继续。启用态将 `scorecard.json` 纳入 checkpoint、manifest 与锚定完整性；禁用态保留原有工件集合。Watch for: 无已确认的严重或重要缺陷。

**Verdict**: APPROVED

## High-level view

Scorecard 只在显式启用后进入运行图。Train 是唯一拟合输入；Test 与 Holdout 仅生成分区级计数、均值和极值摘要，未持久化实体、样本行或逐行预测数组。

完整性校验只接受原有集合或带 `scorecard.json` 的扩展集合，并按 manifest 中实际声明的工件计算哈希。

### Train 拟合与冻结分区评分

`_scorecard_payload` 仅将 `train` 传给 `fit_scorecard`；Test 和 Holdout 仅传给已拟合模型以生成摘要。拟合出现 `TypeError` 或 `ValueError` 时，节点写出 `unavailable`，验证节点仍继续执行。

### 可选工件的不可变发布

启用时 scorecard 节点会 checkpoint `scorecard.json`，最终 manifest 同时记录其摘要和大小。`_is_complete_run` 仅接受精确的旧或扩展工件集合；禁用路径仍发布旧集合。
