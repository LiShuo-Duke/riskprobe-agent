# Host 决策失败投影

本改动将 host decision runner 的失败投影为受限的 `context` 失败对象，并把服务阶段异常映射到固定白名单码；正常路径仍按既有 `inspect → diagnose → discover → recommend → review` 返回 terminal 结果。Watch for: **confirmed** — 对失败会话调用 submit 时，MCP server 仍抛出 `HostDecisionError`；MCP 将其编码为通用错误内容，而不是仅含 `phase` 和白名单 `error_code` 的受限载荷。

**Verdict**: NEEDS_CHANGES

## High-level view

`get_decision_context` 的 runner 异常会持久化为 `HostDecisionFailure`，其字段限定为 `phase: context` 与 allowlist `error_code`。服务节点也用 `HostSafeStageError` 隔离底层原因，成功的两阶段流程未改变。

失败 session 的 submit 拒绝未经过同一投影。MCP 工具让异常穿过 transport，产生通用错误文本而不是规定的最小 context 失败载荷。

### 失败会话的 submit 未保持受限失败协议

`HostDecisionCoordinator.submit_proposal` 在失败 session 没有 context 时抛出 `HostDecisionError`。`riskprobe_submit_decision_proposal` 未捕获或投影该异常，因此 transport 产生通用 MCP error，而不是 `HostDecisionFailure`。这违反失败 MCP payload 只能含 context phase 和白名单错误码的边界；现有测试只断言 get-context 失败的安全结构，未覆盖失败后 submit 的 MCP 响应。应在 MCP 边界将此拒绝转换为同一受限失败 DTO，并新增端到端断言其完整 payload 与无异常文本。

</details>
