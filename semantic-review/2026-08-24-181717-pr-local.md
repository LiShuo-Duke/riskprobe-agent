## Aggregate terminal projection and replay

`riskprobe_get_decision_context` returns `HostDecisionContext | HostDecisionNoActionOutcome | HostDecisionFailure`, matching the coordinator’s public outcomes without adding an MCP operation or input parameter. `HostDecisionNoActionOutcome` is strict: its payload contains only the protocol version, terminal phase and reason, empty actions, and a clean five-step successful agent result. The regression asserts the exact public field set and confirms the response has no context, proposal, evidence, or path value.

`riskprobe_submit_decision_proposal` keeps its four existing inputs. For the same idempotency key, the coordinator detects the stored no-action terminal before proposal validation or persistence, so valid public placeholder arguments return the exact terminal payload and do not create a decision/run artifact. This preserves the bounded proposal contract for awaiting-proposal sessions while safely tolerating a replay attempt after a terminal result.

## Terminal-first Host instructions retain the normal gate

Both Host documents make `phase="terminal"` with `terminal_reason="no_actionable_diagnosis"` final on the first call. They prohibit a proposal call and require reporting the completed `inspect → diagnose → discover → recommend → review` sequence, no diagnosis/action/proposal, and the continuing manual-approval limitation.

The `awaiting_proposal` branch remains separate. It limits the Host to aggregate context, requires every finding and evidence ID in order, preserves action count and allowlist limits plus Grade-B restrictions, and requires the original context ID and complete unchanged diagnosis evidence IDs for the single proposal call.
