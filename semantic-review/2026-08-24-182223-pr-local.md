# Five-step no-action terminal

Empty diagnoses now complete the fixed `inspect → diagnose → discover → recommend → review` sequence without entering the Host proposal gate, while non-empty diagnoses retain the context → proposal → terminal flow. Live execution and terminal replay independently derive `no_action_required` only from an explicit empty diagnose response with no tool, permission, payload, or evidence-resolution failure. Watch for: **confirmed** existing `riskprobe.agent-result.v1` sidecars cannot be decoded after this additive `ReviewDecision` field, so completed cached runs fail closed on restart instead of replaying.

**Verdict**: NEEDS_CHANGES

## High-level view

The no-action branch preserves the five public stages but skips decision-controller preparation, Host context creation, and proposal evidence. Live execution and replay use the same empty-diagnosis and safety-failure predicates; the clean terminal permits neither diagnostic nor action evidence.

Host-session persistence treats a no-action outcome as terminal only when it has neither context nor proposal, then reconstructs the same strict aggregate-only union after restart. The public context MCP tool exposes that union with its idempotency-key-only input; the Host instructions terminate on it and retain the evidence-bound non-empty branch.

## Existing terminal-result sidecars become unavailable after upgrade

**confirmed** — `ReviewDecision.no_action_required` has a safe in-memory default, but `src/riskprobe/agents/results.py:226-241` requires that key in every persisted review payload while retaining `_FORMAT_VERSION = "riskprobe.agent-result.v1"`. A valid sidecar written by the base revision therefore raises while `_reconstruct_result` indexes the missing key. `RiskProbeService.orchestrate` converts that cache-load failure into `HostSafeStageError("agent_state_unavailable")` (`src/riskprobe/service.py:1960-2015`), so restart or repeat execution of an already completed normal session fails closed instead of returning its verified terminal result.

Failing closed protects the data boundary, but it breaks durable idempotent replay and changes the documented persistence contract without a format version change. Decode absent keys as `False` for v1 records, or introduce a new format with an explicit migration path. The current tests round-trip only records produced by the new encoder; they do not exercise a pre-change payload, the service-level cached-result reload, or a no-action service restart.

## Empty diagnosis remains aggregate-only across execution and replay

The executor records an explicit empty diagnosis, completes discovery and recommendation with empty evidence, and derives the no-action review only if no tool, permission, unsafe-payload, or evidence-resolution failure was observed. The replay validator repeats those predicates and verifies the five-stage sequence and evidence chain. `HostDecisionNoActionOutcome` additionally requires success, the no-action review marker, no action or evidence IDs, and the exact five-step sequence before it can be returned without a context or proposal.

## Host boundary and instructions keep the normal proposal gate

The Host-session sidecar rejects no-action terminals that carry a context or proposal and restores the terminal union after coordinator restart. The MCP context operation accepts only `idempotency_key` and returns context, no-action terminal, or safe failure; the proposal operation retains its bounded inputs. The updated Host skill and system prompt stop on `no_actionable_diagnosis`, while awaiting-proposal still requires the original context ID, complete diagnosis evidence, allowlisted actions, and manual approval.
